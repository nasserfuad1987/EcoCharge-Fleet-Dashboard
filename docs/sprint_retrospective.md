# Sprint Retrospective — Provisional Draft (approximately 150 words)

*This draft refers only to observable repository work. The group must review and revise it at the actual end of the sprint; do not imply meetings, teammate contributions, or peer reviews that did not occur.*

The EcoCharge prototype demonstrates that a limited feature set can still support meaningful software engineering. Separating fixed vehicle data, the calculator, Flask routing, and presentation made responsibilities clearer. Explicit acceptance criteria and automated tests also created a repeatable way to check correctness rather than relying solely on a visual demonstration. The most important improvement was moving duration validation into server-side logic; browser restrictions alone would not prevent crafted negative or invalid requests. We also added an ethical review of how future location tracking might affect drivers.

One area requiring further work is collaboration evidence. The initial pull requests were merged from a single connected GitHub account, so they do not independently demonstrate a full team review process. Before the final submission, each member should contribute identifiable work, provide genuine review feedback, and document decisions. Next time, we would establish task ownership and review checkpoints earlier, allowing more time for testing, feedback, and refinement.
